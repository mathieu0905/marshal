# 实验计划：已知候选仓跨仓评测

日期：2026-08-25
设计依据：`benchmarks/cross-repo-pr-impact/CANDIDATE_BOUNDED_DESIGN.md`

## 问题与主张

**问题**：给定源仓变更、项目内已知候选仓和时点代码，系统能否排序需要检查或适配的候选仓，并在有执行条件时给出受证据约束的判断？

**主张 C1**：固定候选边界可以形成非平凡的跨仓目标排序任务，而不把托管平台仓库发现能力混入评测。

**主张 C2**：历史适配和因果破坏可以复用同一输出接口，但必须按 E1/E2 分开计分；A3 和完整负空间不应成为每条因果正例的准入条件。

**主张 C3**：仓库排序和真实组合执行是互补能力；repo-local pass 或未执行不能升级成跨仓 pass。

本计划不主张开放世界关系发现、完整影响集合、通用误报率或自动多仓合并。

## 实验对象

### E1 历史适配材料

- 当前 100 条案例；
- 12 个候选目录，规模 4 至 14，平均 8.33；
- 1078 个案例-仓库时点组合；
- 当前仅作 development material，正式使用前需要 catalog provenance 和关系隔离 split。

### E2 因果材料

- OpenDev 失败到恢复储备；
- 已完成的 A0/A1/A2 主动重放；
- 满足相同三臂条件的历史锚点；
- 缺 E3 或 E4 不会淘汰严格 E2。

### E3/E4 支持材料

- 已确认消费变化表面的限定负例；
- 已确认兼容变化进入消费表面的 A3；
- 分别报告，不拼接到不相关 E2 案例。

## 实验模块

### B0：候选目录来源审计

- **目的**：证明候选边界不是按隐藏答案生成。
- **工作**：为每个目录记录来源规则、生成时间、仓库纳入理由和使用案例；核对生成脚本中 targets 与 `DISTRACTORS` 的贡献。
- **处置**：可由独立项目名录重建的目录进入后续；单例目录进入 development/catalog-sensitivity；无法证明的目录不进正式主分数。
- **指标**：可无标签重建目录数、仓库重合率、目录规模、单例目录数、目标遗漏数。

### B1：关系隔离划分

- **目的**：防止同一有向关系、源提交族或修复模板跨 split。
- **工作**：折叠仓库别名和模块；按共享有向关系形成案例组；再按机制与修复模板合并组；生成 development/evaluation/holdout 提案。
- **指标**：组数、各 split 案例和关系数、项目/年份/目录规模分布、跨 split 冲突数。
- **验收**：跨 split 冲突为 0；人工确认后再更新正式索引。

### B2：证据重分类

- **目的**：盘点已有材料，不再用完整四臂项目包作为唯一单位。
- **工作**：按 E0-E4 crosswalk 重标 case 和 workstream；`executed`、`ci_contrast_proven` 逐条复核 A0/A1/A2。
- **指标**：各层独立源变化、根仓、有向关系数；从候选到接纳的产率；中位准备时间；拒绝原因。
- **验收**：E1/E2 可机器汇总；E3/E4 有明确命令范围；没有未执行候选被标为负例。

### B3：候选代码排序开发运行

- **目的**：验证系统真实读取候选代码，而不只是使用仓库名先验。
- **输入**：development split 的纯代码源差异、候选目录和时点快照；关闭网络；隐藏目标修复与标签。
- **方法**：random/order、same-owner/name、label-frequency diagnostic、flat multi-repo review、Marshal 当前配置、Marshal 排序适配。
- **指标**：MRR、Recall@1/3/5、known-target recall、平均预测仓数、输入/输出失败和稳定性。
- **验收**：至少一个代码读取方法超过非语义策略，且不能由全报候选解释。

### B4：E2 执行诊断

- **目的**：区分找到目标、找到检查和真实验证三步。
- **条件**：只使用通过 B2 的 E2。
- **指标**：目标找回、检查位置找回、命令可运行率、端到端失败/恢复判断、`not_assessed` 比例。
- **分母**：全部 E2 目标；漏报和未执行不得从分母删除。

### B5：E3/E4 克制测量

- **E3**：只有 bounded universe 的正负候选完整判定时报告 precision/specificity；否则只报 false-alarm、abstention 和预测数量。
- **E4**：报告空预测率、预测数量和错误升级率。
- **边界**：结果只适用于已执行任务和固定输入。

## 运行顺序

| 阶段 | 模块 | 继续条件 |
|---|---|---|
| D0 | B0 catalog audit | 至少两个多案例目录可无标签重建 |
| D1 | B1 split proposal | 跨 split 关系/模板冲突为 0 |
| D2 | B2 evidence migration | E1/E2 可独立汇总，E3/E4 有范围 |
| D3 | B3 small development run | 端到端输入与输出可运行 |
| D4 | B3+B4 development measurement | 代码读取产生可解释增益 |
| D5 | 固定设置后 evaluation/holdout | 不从正式标签调规则 |

## 暂停和保留

- 暂停扩大到 30 至 50 个完整四臂项目包；
- 暂停为了补 A3 或多仓负空间继续筛新的 FSE 家族；
- 保留所有历史日志、拒绝项、三臂和四臂结果；
- 新出现的低成本自然 E2 可以登记，但不能挤占 D0-D3；
- schema v1 暂不修改，证据不足使用 `not_assessed`。

## 风险与处理

| 风险 | 处理 |
|---|---|
| 候选目录由答案派生 | B0 审计；无法独立重建则不进正式分数 |
| 关系频率泄漏 | 组级 split；frequency 只作诊断上界 |
| 未标注候选被当错例 | 主集额外预测记 `unjudged` |
| 未执行被当无影响 | 使用 `not_assessed`；`no_cross_repo_impact` 限于 E3 |
| 重复模块抬高样本量 | 根仓和有向关系为统计单位 |
| 旧缓存制造假绿 | 保留现有独立依赖目录、版本核对和消费证明 |

这些要求是评测解释条件，不是产品 gate。当前不新增内容 hash、冻结 contract 或固定 baseline。
