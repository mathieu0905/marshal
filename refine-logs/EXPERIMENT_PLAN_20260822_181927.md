# 实验计划：Proof-Bound Cross-Repository Review

**Problem**：单仓 review 无法证明 consumer 实际消费了跨仓候选变化，可能对错误组合给出假绿或假红。
**Method Thesis**：跨仓 `passed` 必须绑定 exact composition、真实执行和 consumption proof；否则显式 `not_assessed/not_run/unknown`。
**Date**：2026-08-22

## Claim Map

| Claim | Why It Matters | Minimum Convincing Evidence | Linked Blocks |
|---|---|---|---|
| C1：proof-bound composition 降低 unsupported compatibility conclusions | 这是核心可信度问题 | C3 相对 C0-C2 显著降低 false-compatible rate，同时 green FPR 可控 | B0, B1, B2 |
| C2：方向 edge 与定向执行在固定预算下提高影响定位与证据质量 | 排除“只是多给代码” | C2 相对 C1 的 routing 收益；C3 相对 C2 的 execution 收益 | B1, B3 |
| Anti-claim：增益不是更大上下文、更多工具调用或模型变化 | 防止混杂 | 相同 repo set/model/prompt/budget；报告 tokens/tools/builds/cost | B1, B3 |

## Paper / Product Storyline

- **主结果必须证明**：C3 在可重放 Maven dependency updates 上减少 unsupported-pass/false-compatible，并提供有效 consumption evidence。
- **辅助结果**：affected-consumer ranking、文件定位、成本和稳定性。
- **Appendix / 后续**：OpenDev/Zuul coordinated refs、Cowboy wallet/node artifact handoff。
- **明确删除**：D0 前不加入 LLM、自动 relation discovery、Cargo、wire/schema、内容 hash、冻结 baseline 或 project gate。

## 数据构造

### Positive pool

BUMP commit `324d5513aa5c` 的候选池：28 个重复 update packs、78 个 compilation/test positives、11 个 provider repos。每个 positive 重新执行一次 pre-pass/candidate-fail 检查；无法重放、网络依赖或 flaky case 排除并记录。

### Green controls

同一 `(GAV, old, new)` 的真实 green bot PR 优先；不足时从 Breaking Bad/client graph 选历史 consumer 并重放合成升级。接受条件为 pre/candidate 各 `2/2` pass，且 dependency tree 确认 candidate version 生效。

### Final unit

分析单位是 update pack，不是单 consumer：

```text
provider repo + GAV old->new + 2-4 failing consumers + 2-4 verified greens
```

目标 18-24 packs、72-192 consumer cases。若最终 test 不足 18 packs、8 个 unseen provider components 或 60 consumers，则结果降级为 case study。

### Split

按 provider-repo ↔ consumer-repo connected components 分约 15% calibration、20% development、65% held-out test。同 provider family/release series、consumer、fork 不得跨 split。

## 信息隐藏

受测系统不可见：BUMP JSON、failureCategory、reproduction logs、CI/check status、PR title/body/comments、最终修复、后续 commits。受测环境禁访 GitHub PR/Actions/搜索接口；允许使用准备好的源码、依赖缓存和 release 当时已公开代码。

每个 case 的 evidence metadata 记录 `oracle_visibility=hidden_from_reviewed_system`。隐藏 oracle 独立决定 positive/green；系统输出不能反向影响标签。

## 四个受控条件

| Condition | Visible repos | Direction edge | Repo-local execution | Candidate composition | 解释 |
|---|---|---|---|---|---|
| C0 single-repo | provider only | no | provider only | no | 当前单 PR 上限 |
| C1 flat-context | provider + identical consumers | no | yes, current state | no | 多仓代码/context 的价值 |
| C2 directional-no-exec | same as C1 | sourced GAV edges | same as C1 | no | direction/routing 的价值 |
| C3 proof-bound | same as C1/C2 | same as C2 | yes | yes | composition + proof 的增量 |

所有条件：

- 同一模型、推理深度、任务措辞和总 token/tool/wall-time budget；
- 每 pack/condition 3 次 fresh sessions；
- consumer 顺序随机，condition 顺序 Latin-square；
- 48 小时窗口内完成同一实验批次并记录模型标识/日期；
- timeout/tool failure 按无定位计，同时报告执行失败率，不在 test case 上事后补跑。

## Experiment Blocks

### B0：D0 Data Feasibility

- **Claim tested**：BUMP update packs 能否形成带 green controls 的可信主评测。
- **Why**：数据不可行时，任何模型比较都没有意义。
- **Dataset**：3 packs / 3 providers，至少一个 compilation 和一个 test pack，每 pack ≥2 positives。
- **Runs**：positive replay、green mining、2/2 green replay、resolution verification、Maven adapter dry run。
- **Metrics**：positive replay rate、green controls per pack、attrition reason、pair wall time、disk/network。
- **Success criterion**：3 packs 全重放、≥6 positives，至少 2 packs 各有 2 greens；资源不超上限。
- **Failure interpretation**：降级 case study 或停止 BUMP route，不扩产品机制。
- **Priority**：MUST-RUN FIRST。

### B1：Main C0-C3 Comparison

- **Claim tested**：C3 是否降低 false-compatible 并改善 break detection。
- **Dataset**：held-out component split；只有 D0/D1 数据质量合格后执行。
- **Compared systems**：C0、C1、C2、C3。
- **Primary metrics**：false-compatible rate、repo F1/MCC、green FPR、3-class macro-F1、pack-macro MAP/Recall@5。
- **Secondary metrics**：nDCG@5、Recall@3、file Recall@5/MRR、cost、stability。
- **Success criterion**：见“研究决策标准”。
- **Failure interpretation**：C3 无增益说明不要继续产品化；C1≈C3 说明 graph/proof 未提供独立价值。
- **Table target**：主表，pack-macro accuracy + evidence + cost。
- **Priority**：MUST-RUN。

### B2：Unsupported-Pass and Proof Audit

- **Claim tested**：proof-bound semantics 是否阻止“命令绿但未消费 candidate”的错误结论。
- **Dataset**：positives、verified greens，以及 development 中构造的 overridden/missing-resolution cases；后者不进入主要 break metric。
- **Compared systems**：C1/C2/C3。
- **Metrics**：unsupported-pass rate、proof validity、assessment coverage、`not_assessed` precision、executable-evidence rate。
- **Audit**：分层抽取 20% findings；两名盲审检查 path/symbol、resolved dependency、因果相关性，第三人裁决。
- **Success criterion**：C3 proof validity ≥0.90，unsupported-pass 显著低于 C1/C2，不能靠全部 abstain 达成。
- **Failure interpretation**：若 coverage 很低，语义虽保守但产品价值不足。
- **Figure target**：assessment coverage vs unsupported-pass 曲线。
- **Priority**：MUST-RUN。

### B3：Novelty Isolation and Simplicity

- **Claim tested**：direction 与 execution 的增益可分别解释；确定性 V0 是否足够。
- **Comparisons**：C1→C2 测 edge/routing；C2→C3 测 composition/proof。
- **Metrics**：paired delta in MAP/Recall@5/F1、opened files、built repos、tokens、wall time。
- **Success criterion**：C2 相对 C1 有准确率增益，或准确率相当但检索/打开文件成本降低 ≥30%；C3 相对 C2 降低 false-compatible ≥0.08。
- **Simplicity rule**：如果 deterministic C3 达标，不新增 LLM。只有 D1 定位明显不足时，才把 typed LLM proposer 作为后续 ablation。
- **Priority**：MUST-RUN；LLM variant CUT by default。

### B4：External Product Case Study

- **Claim tested**：Maven 结论能否迁移到 Marshal 的真实 wallet/node artifact handoff。
- **Dataset**：一个明确 wallet provider ref + node consumer ref/companion change。
- **Evidence**：wallet 生成真实 artifact/bytes，node 直接消费；不得用 node self-roundtrip 替代。
- **Success criterion**：能够区分当前 reporter `not_run`、tip self-test 和真实 artifact handoff。
- **Failure interpretation**：BUMP 结果不能外推到 Cowboy。
- **Priority**：NICE-TO-HAVE，post-GO only。

## Metrics

### Primary

- pack-macro MAP、Recall@5、repo F1/MCC；
- green false-positive rate；
- `no impact / compilation / test` macro-F1；
- unsupported-pass / false-compatible rate；
- proof validity 与 executable-evidence rate。

### Secondary

- Recall@3、nDCG@5、first relevant MRR；
- compiler/stack-trace project file Recall@5（无可靠 oracle 时 N/A）；
- tokens、tool calls、opened files、built repos、wall time、API cost；
- repeat prediction-set Jaccard、classification agreement；
- human evidence audit Cohen's kappa。

## Statistical Plan

- 分析单位为 held-out pack；不把同 pack consumers 当独立样本。
- 四条件连续/排序指标先做 Friedman test。
- 预先指定 C3-vs-C0、C3-vs-C1、C3-vs-C2 paired exact Wilcoxon，并做 Holm correction。
- 报告 median paired delta 和 rank-biserial effect size。
- 按 provider connected component 做 10,000 次 paired bootstrap，给 MAP/Recall/F1 delta 的 95% CI。
- consumer-level McNemar 只作补充。
- test provider components ≥10 时才考虑 mixed-effects logistic model；否则不依赖渐近 p-value。
- 决策看 effect + CI + evidence quality，不以 `p<0.05` 单独决定。

## Compute and Data Budget

- **GPU**：0 GPU-hours。
- **机器**：16-32 vCPU、64 GB RAM、150 GB SSD。
- **Oracle builds**：约 450-500 次（取决于 green mining）。
- **CPU**：先按 60-120 CPU-hours 预算，D0 实测后修订。
- **System runs**：18 packs 时 `18×4×3=216`；28 packs 上限为 336。
- **Turnaround**：按 15 min/run，216 runs 串行约 54h，8 路约 7-10h 加调度开销。
- **Hosted model**：上限估计 30-40M tokens；D0/D1 实测后收紧。
- **人力**：数据准备 3-5 engineer-days；evidence audit 6-10 person-hours。
- **存储**：按 case 拉 GHCR image，不加载 149.9 GB 全量 tar；峰值约 80-150 GB。

## Research Decision Criteria

这些标准只决定研究投入，不是产品 gate 或冻结 baseline。

### GO

- 数据：held-out ≥18 packs、≥8 unseen provider components、≥60 consumers，compilation/test positives 各≥15；
- C3 vs C0：MAP 或 Recall@5 绝对提升 ≥0.15，paired 95% CI lower bound >0；
- green FPR ≤0.20，3-class macro-F1 ≥0.60；
- proof/evidence correctness ≥0.80，重复一致率 ≥0.75；
- C2 vs C1：准确率 +0.08，或准确率在 ±0.03 内但检索成本下降 ≥30%；
- C3 vs C2：false-compatible 绝对下降 ≥0.08，且不是靠普遍 abstention。

### REVISE

- 主要提升 0.05-0.15 或 CI 跨 0；
- green FPR ≤0.25；
- 错误集中在 development 已能定位的 edge/resolution/adapter 问题。

只允许基于 development 做一次针对性迭代；held-out test 不能调参后原地重跑，应保留二级 holdout 或补新 packs。

### NO-GO

- C3 vs C0 提升 <0.05；
- C2 对 C1 没有准确率或效率价值；
- C3 对 C2 没有 false-compatible/evidence 改善；
- green FPR >0.30、evidence correctness <0.70；
- 数据重放淘汰 >25%。

NO-GO 表示停止扩大跨仓产品实现，回到数据质量或依赖映射，不增加更多门禁。

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| green controls 不足 | D0 两天止损，降级 case study |
| BUMP 只覆盖 Maven | 不外推；Cowboy 独立 case study |
| provider/consumer 泄漏 | component split + hidden post-change artifacts |
| LLM 预训练见过旧代码 | provider-exclusive split、隐藏 PR/CI、要求可核验证据 |
| 执行成本吞噬预算 | 同预算报告，D0 测量后定并发/timeout |
| repo 已经失败 | pre-state paired control；无法归因则 incomplete |
| 全部 abstain 获得低 false-pass | 同时报 assessment coverage 和 break recall |
