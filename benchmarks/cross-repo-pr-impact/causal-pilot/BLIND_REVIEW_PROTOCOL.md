# 因果案例独立盲复核协议

## 目的

复核者判断一个执行组合是否真正证明“源差异引起失败，所提目标仓修改修复了该失败”。复核单位既包含初次接受项，也包含高相似度拒绝项。复核者在提交判断前不能查看初次语义决定、因果标签或汇总文档。

`blind-review-packet.jsonl` 只提供 14 个去重转换的结构证据入口，共涉及 33 个任务。它不包含初次复核的决定、理由、影响类型、失败签名或接受状态。14 个转换覆盖当前全部 6 个强因果储备和 8 个语义拒绝项。

## 可见材料

复核者可以读取每条记录中的：

- 源变更前后补丁集、源代码差异纯度和源变更页面；
- 所提目标变更、目标提交和目标补丁；
- 每个结构通过任务的失败与成功日志；
- 两臂实际提交清单核验、时间顺序和构建引用信息。

复核者不得读取：

- `candidates/ci-contrast-semantic-review.jsonl`；
- `results/opendev-rolling-*/semantic-review.jsonl`；
- `causal-pilot/labels.jsonl`、`README.md` 和 `../AUDIT.md` 中的案例结论；
- 其他复核者已经提交的答案。

## 判断顺序

1. 比较源前后补丁，确认增加协调说明时源代码差异没有变化。
2. 核对失败臂实际采用源提交且不含目标提交，成功臂采用同一源代码差异并包含所列目标提交。
3. 从失败日志提取具体失败签名，判断它是否执行了源变化涉及的行为。
4. 阅读目标补丁，判断修改是否直接处理该失败机制，而不是外部环境、偶发超时或无关任务变化。
5. 在成功日志中确认同一路径恢复；仅有任务最终状态为成功不够。
6. 分别填写“源是否引起失败”和“目标是否修复失败”，再给出总决定。

只有两个问题都回答“是”时才能接受。材料暂时不可访问时填写 `evidence_unavailable`，不能把证据缺失写成拒绝。多个任务共享同一源和目标时仍是一个复核单位；每个任务都要判断，但不能重复计数为多个案例。

## 输出

每条记录输出一个符合 `blind-review-response-schema.json` 的对象。人工和模型复核必须在 `reviewer_kind` 中区分；模型复核不能表述为第二位人工标注者。完成后再与初次决定比较，报告接受与拒绝的一致率、逐项分歧、证据不可得项和最终裁决。

生成盲审包：

```bash
python benchmarks/cross-repo-pr-impact/build_causal_blind_review_packet.py
```

生成脚本会按源变更去重，并拒绝同一源在多个非重复批次中出现；它不执行复核，也不会把初次决定复制到盲审包。
