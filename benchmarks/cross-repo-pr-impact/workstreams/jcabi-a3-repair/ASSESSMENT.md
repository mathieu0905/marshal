# jcabi-aspects A3 修复评估

## 结论

`jcabi-aspects` 在当前四个固定消费仓与原生命令组成的闭集中，没有找到合格的共同 A3。项目包应固定为**永久三臂破坏案例**：保留已经成立的 A0（破坏前）、A1（只升级源依赖后失败）和 A2（应用维护者修复后恢复），撤销原先把 `0.22.2 -> 0.22.3` 当作 A3 的判断，也不再用“相邻两个版本都绿色”补第四臂。

这里的“永久”限定于当前闭集与测试合同。以后只有更换消费仓闭集，或者新增能够在四仓共同触及同一真实变化表面的原生检查，才可以重新评估；重复运行现有绿色任务不能改变结论。

## 判定标准

兼容变化 A3 不只要求相邻发布在四仓中都通过，还要求四仓原生检查共同触及该发布的真实变化表面。否则两侧绿色无法区分“变化兼容”与“测试根本没有观察变化”。本轮先读相邻标签的源码差异，再对有明确行为语义的候选执行双臂，并用覆盖或定向断言核对变化方法是否进入测试。

## 相邻发布审计

原 A3 `0.22.2 -> 0.22.3` 的关键行为变化位于 `MethodValidator`：新版本选择性忽略 Hibernate Validator 的 `HV000151` 参数约束覆盖异常。已有四仓执行虽然两侧都通过，但没有测试触发这个异常分支，因此原 A3 不成立。

随后审计了其后的主要相邻发布：

| 相邻发布 | 主要变化表面 | 对当前闭集的判断 |
|---|---|---|
| `0.22.3 -> 0.22.4` | `MethodCacher` 缓存行为 | 没有四仓共同观察面 |
| `0.22.4 -> 0.22.5` | `MethodLogger` 修复 | 没有四仓共同观察面 |
| `0.22.5 -> 0.22.6` | `RetryOnFailure` 日志行为 | 只覆盖部分消费仓 |
| `0.22.6 -> 0.23.1` | 行为重构与构建清理 | 没有可由四仓共同定位的变化表面 |
| `0.23.1 -> 0.23.2` | POM 与构建配置 | 不构成四仓共同执行的行为变化 |
| `0.23.2 -> 0.24.1` | 大规模内部与构建重构 | 没有可由四仓共同定位的变化表面 |
| `0.24.1 -> 0.25.1` | 删除公开类 `Tv` | 已用作破坏臂，不能再充当兼容 A3 |
| `0.25.1 -> 0.26.0` | Java 21 与构建依赖迁移 | 不满足当前 Java 11 四仓合同 |

这些版本对没有进入双臂正式候选，不是因为未能取得普通绿色结果，而是因为源码审计先行表明它们缺少四仓共同可观察的真实变化。

## `0.20.1 -> 0.20.2` 的真实变化

更早的相邻发布 `0.20.1 -> 0.20.2` 提供了本轮最强候选。`ImmutabilityChecker` 原来主要检查字段的声明类型；`0.20.2` 把被检查对象传入递归过程，新增并调用 `checkDeclaredAndActualTypes(...)`，从而同时检查字段的声明类型和实际运行时类型。上游 `ImmutableTest` 也解除了一项忽略，专门验证“声明为不可变接口、实际实现可变”的对象会被拒绝。

这是一项真实且有上游判例的行为变化。它所在的完整发布还包含日志、构建与其他内部修改，因此本轮不把整个发布的所有结果单因归因于 `ImmutabilityChecker`；A3 是否成立只依据四仓是否共同观察到这项候选变化。

## 四仓双臂结果

固定四个消费仓的原提交，只把 `com.jcabi:jcabi-aspects` 从 `0.20.1` 替换为 `0.20.2`，在 OpenJDK 11.0.31 下运行原生命令。八条主命令的退出码全部为 0：

| 消费仓 | 命令 | `0.20.1` | `0.20.2` |
|---|---|---|---|
| `jcabi-s3` | `mvn -B clean test` | 12 项通过 | 12 项通过 |
| `jcabi-simpledb` | `mvn -B clean test` | 5 项通过 | 5 项通过 |
| `jcabi-w3c` | `mvn -B clean test` | 9 项通过 | 9 项通过 |
| `jcabi-maven-plugin` | `mvn -B clean verify` | 5 个 Invoker 场景通过 | 5 个 Invoker 场景通过 |

输入差异、命令、日志、退出码与耗时保存在 `../../results/jcabi-a3-repair-0.20.1-0.20.2-java11-screening-2026-08-24/`。这些结果只证明完整发布在固定命令下均未造成失败，不能单独证明四仓测试观察了行为变化。

## 变化表面覆盖

对 `0.20.2` 使用 JaCoCo 0.8.12，并把报告限定到 `com.jcabi.aspects.aj.*`：

| 消费仓 | `ImmutabilityChecker` | `checkDeclaredAndActualTypes(...)` | 判断 |
|---|---:|---:|---|
| `jcabi-s3` | 0 条指令、0 行 | 0 条指令、0 行 | 未加载变化类 |
| `jcabi-simpledb` | 152 条指令、40 行 | 22 条指令、8 行 | 命中真实变化方法 |
| `jcabi-w3c` | 0 条指令、0 行 | 0 条指令、0 行 | 未加载变化类 |
| `jcabi-maven-plugin` | 无该变化面的定向覆盖 | 无 | `ajc` 夹具使用 `@NotNull` 验证 `MethodValidator`，不使用 `@Immutable` |

SimpleDB 还分别覆盖 `after` 5 行、`check` 11 行和 `fields` 9 行，能够确认新增调用路径实际进入测试。S3 与 W3C 的覆盖数据文件都只有 46 字节，XML 中 `ImmutabilityChecker` 所有计数为零。Maven Plugin 的真实集成夹具位于 `src/it/ajc`，测试的是参数约束切面，不触及不可变性检查。

所以这项真实行为变化只被四仓中的一个仓观察到。其余三个仓的绿色结果是未覆盖变化表面的绿色，不能作为兼容变化负空间。

## 最终处置

1. 拒绝 `0.22.2 -> 0.22.3` 原 A3，因为 `HV000151` 分支没有进入现有测试。
2. 拒绝 `0.20.1 -> 0.20.2` 替代 A3，因为只有 SimpleDB 命中真实变化方法。
3. 不接受其余相邻发布的普通绿色版本对；源码审计已表明它们没有四仓共同变化表面。
4. `jcabi-aspects` 不计为完整四臂项目包，固定保留为永久三臂破坏案例。现有破坏与恢复证据仍然有效，本结论只撤销兼容 A3，不降低 A0/A1/A2 的证据等级。
