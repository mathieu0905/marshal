# org.json 20131018 的 FSE 关系族筛选

更新日期：2026-08-25

## 结论

FSE 2024 的精确候选框包含两条记录，分别来自 `likethecolor/Alchemy-API` 和 `codeforamerica/open311_java`。两条公开执行记录都命中同一个源行为变化：`JSONObject.getString` 从把数字等非字符串值经 `toString()` 强制转换，改为只接受实际 `String`，否则抛出 `JSONException`。

这个变化可以定位到源提交 `f4cb14728f13629972a0ea76bb3dc0705a735fa8`，并确认包含在 Maven Central 的 20131018 发布源中。但两仓的全部远程历史始终固定 20090211，从未声明 20131018，也没有保持 20131018 输入的维护者修复。FSE 工件又没有保存目标 Git 修订。因此本轮接纳 0 条，不执行三臂，不生成手工 A2，也不构造限定负例或 A3。

## 源版本与机制

Maven Central 仍提供 20090211 和 20131018 的二进制。20090211 没有源 JAR，且发布时间早于当前上游 Git 历史，因而不能把某个后来的 Git 提交误称为它的精确发布修订。直接对已发布二进制运行最小探针时，输入 `{"value":12312313121}` 在两个版本中都解析为 `Long`；20090211 的 `getString("value")` 返回 `12312313121`，20131018 则抛出 `JSONObject["value"] not a string.`。

20131018 的 Central 源 JAR 可以精确恢复。其 17 个 Java 文件在统一 CRLF 后与提交 `34f327e6d070568256b314479be158589d391891` 全部一致。提交 `f4cb14728f13629972a0ea76bb3dc0705a735fa8` 是该修订的祖先；它把 `JSONObject.getString` 的实现从 `object.toString()` 改为 `instanceof String` 检查和异常。最小行为差异保存在 `source-mechanism.patch`。

FSE 字段中的 `20090911` 不能恢复为正式 `org.json:json` 发布：它不在当前 Central 元数据的版本列表中，对应二进制也不存在。它只保留为原始候选的 `previous_version` 字段，不能用作额外 A0 或源修订锚点。

## Alchemy-API 历史

镜像共有 32 个引用和 82 个唯一可达提交，包含分支、标签和拉取请求引用。默认分支头为 `5208cfc92a878ceeaff052787af29da92d98db7e`。每个包含 POM 的可达版本都把 `json.version` 固定为 20090211；没有 20131018 声明。

公开堆栈的断言位于 `AbstractParserTest.java:324`，与远程历史中的测试 blob `5f2ea027b12e1df1feaba771703e302864babb19` 一致。但该 blob 出现在 34 个可达提交中，从 2014 年的 `740a9b3c5c1cead512c5fd050eb361193f6c75f9` 延续到 2017 年拉取请求合并引用，不能据此唯一恢复 A1 修订。

客户端 `AbstractParser.getString` 捕获 `JSONException` 后返回 `null`，所以 20131018 对数值字段的严格检查精确解释了公开的 `expected 12312313121 but was null`。20131018 发布后的历史仍保留这项调用和异常路径，测试也继续要求数字强制转换；没有后续代码提交可在固定 20131018 下恢复该合同。

## open311_java 历史

镜像共有 4 个引用和 413 个唯一可达提交。默认分支头为 `e35d30720da51f805eb6a7b15465ed081a6aac11`。提交 `b94b1f67cc88111b8ff84fb00b44012a43fd813a` 首次加入 org.json，版本即为 20090211；此后每个可达 POM 仍保持该版本，没有 20131018 声明。

公开堆栈的 `JSONParserTest.java:159` 与测试 blob `8b3d50a5fdfb675e0a2f4cc406ccdf591364efdd` 一致，但该 blob 同样覆盖 41 个可达提交，不能唯一固定目标输入。客户端辅助方法捕获 `JSONObject.getString` 的异常并返回空串。因此 JSON 数值错误码 `403` 在 20090211 下被强制转换为 `"403"`，而在 20131018 下变为空串；其他两个公开失败也经过同一数值到字符串路径。

仓库最后一个提交的日期为 2013-08-22，早于 20131018 发布。所有引用中均没有发布后的维护者响应，更没有固定 20131018 的修复提交。

## 准入边界

两条记录提供可信的已执行破坏线索和精确源机制，但缺少唯一目标修订以及维护者 A2。手工选择一个匹配的历史提交，把依赖改成 20131018，再把客户端改为 `get(...).toString()`，会制造维护者从未采用的组合。普通测试可以验证这种组合恢复，却不能证明它是维护者对该依赖变化的响应。
