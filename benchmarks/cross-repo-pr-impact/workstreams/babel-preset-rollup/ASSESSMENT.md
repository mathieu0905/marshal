# Babel ES2015 预设到 Rollup 预设的模块保留合同

评估日期：2026-08-24

## 当前结论

这条关系形成 **1 条链独立的高证据因果正例**。`babel-preset-es2015` 从 6.13.0 升到 6.13.1 后改变了导出的插件配置形态；`babel-preset-es2015-rollup` 1.1.1 仍按插件对象做直接索引，未能删除带选项的 CommonJS 转换插件。相同的 ES 模块输入因此被错误转成 CommonJS。采用 1.2.0 的目标代码并使用 `modify-babel-preset` 2.1.1 后，ES 模块语法恢复保留。

本包的限定负例为 **0**，A3 为 **0**。公开数据中的 `localforage-setitems` 与 `postcss-clean` 是同一中间修复关系的两个传播端，不能拆成两个独立目标，也没有执行与 Rollup 预设相同的目标侧合同。

## 公开记录中的版本偏差

Zenodo 数据把两条记录都写成目标从 `babel-preset-es2015-rollup@1.1.0` 修到 1.2.0，并把修复类型标成 `code;version`。公开仓库与下游声明显示，因果边界需要更精确地写：

- `localforage-setitems` 在提交 `9aa6825030b665e70d2f8a5e8f1eadfb25f84d1a` 中声明 `babel-preset-es2015-rollup: ^1.1.1`；
- `postcss-clean` 的初始提交 `c721da5` 同样声明 `^1.1.1`；
- npm 的 1.1.1 发布物使用 `require-relative` 手工删除 CommonJS 插件，正是可稳定重现失败的旧实现；
- npm 的 1.1.0 发布物使用 `modify-babel-preset: ^1.0.0`，结果还取决于当时实际解析到的依赖版本：1.0.0 会失败，1.2.0 在本探针下已经通过。因此仅写“目标版本 1.1.0”不能唯一确定失败环境。

本包据此把 A0/A1 固定到实际下游声明的 1.1.1 发布物，不沿用公开数据中过宽的 1.1.0 标签。两条下游记录只作为传播证据，正式计数仍为一条 `babel-preset-es2015 -> babel-preset-es2015-rollup` 因果关系。

## 源变化与维护者响应

源 6.13.0 保留兼容属性 `.plugins`，其中 CommonJS 转换是一个直接插件对象。6.13.1 改为导出 `preset({})` 的结果，CommonJS 转换成为 `[插件, 选项]`。目标 1.1.1 执行：

```text
plugins.splice(plugins.indexOf(commonjsPlugin), 1)
```

当数组项不再与 `commonjsPlugin` 对象相等时，`indexOf` 返回 -1；调用实际删除最后一个再生器插件，而 CommonJS 插件留在配置中。Issue 7 对这次形态变化、错误删除行为和 `modify-babel-preset` 已加入相应支持做了直接说明。

PR 8 的提交 `9cfb393c48330cdfa2bc9c4add4db503a91a4904` 相对它所在的主分支只改 `package.json`，把 `modify-babel-preset` 从 `^1.0.0` 提升到 `^2.1.1`；`index.js` 在该主分支的 1.1.0 与 1.2.0 标签之间相同。这个 Git 视角保存在 `maintainer-repair.patch`。

但发布物视角不同：npm 1.1.1 来自一个修复分支，采用手工索引代码；npm 1.2.0 回到主分支的 `modify(...)` 代码。因此真实用户从 1.1.1 升到 1.2.0 时同时得到目标代码变化和新辅助依赖。行为相关的发布物差异保存在 `published-artifact-repair.patch`。这两个视角不能混为“PR 8 改了目标代码”，也不能把 1.2.0 的发布编号当成恢复机制。

## 受控重放

探针直接执行项目 README 与 Issue 7 定义的用途：输入含 `export default` 的 ES 模块，经目标预设和 Babel 转换后仍必须保留 ES 模块语法，且不得出现 CommonJS 的 `exports` 或 `require(...)`。目标仓 1.2.0 自带的 `npm test` 只是固定退出 1 的占位命令，不能作为合同。

重放使用 Node.js 6.17.1、Babel Core 6.13.2 和精确 npm 包版本。主要三臂为：

| 臂 | 源 | 目标行为代码 | 辅助依赖 | 目标版本字段 | 结果 |
|---|---|---|---|---|---|
| A0 | 6.13.0 | 1.1.1 | 旧路径 | 1.1.1 | 通过；保留 `export default` |
| A1 | 6.13.1 | 1.1.1 | 旧路径 | 1.1.1 | 失败；输出 `exports.default` |
| A2 | 6.13.1 | 1.2.0 | `modify-babel-preset` 2.1.1 | 故意保留 1.1.1 | 通过；同一错误消失 |

A2 故意不改目标版本字段，已经直接排除发布编号的因果贡献。额外三组贡献对照进一步拆分 1.1.1 到 1.2.0 发布物的变化：

| 对照 | 改动 | 结果 |
|---|---|---|
| CODE_ONLY | 只换 1.2.0 代码，保留旧辅助实现 1.0.0 | 失败 |
| DEPENDENCY_ONLY | 只提供辅助实现 2.1.1，保留 1.1.1 手工索引代码 | 失败 |
| VERSION_ONLY | 只把目标版本字段改成 1.2.0 | 失败 |
| RELEASE_1_2_0 | 1.2.0 代码、辅助实现和版本字段一起采用 | 通过 |

因此 `code;version` 的准确归因是：**发布物代码变化有贡献，新辅助依赖有贡献，目标自身版本字段没有贡献**。二者是联合修复，任一单独变化都不足以恢复。

退出方向、精确解析版本和转换输出保存在 `results/babel-preset-rollup-local-three-arm-2026-08-24/`，重放入口为 `run_three_arm.sh`。

## 负空间与 A3

`localforage-setitems` 和 `postcss-clean` 只是通过 Rollup 预设间接消费源包。它们没有负责“从预设插件列表删除 CommonJS 转换”的实现，也没有在同一固定输入下承担目标侧判断。普通构建通过、未提交配套修改或随后升级依赖，都不足以形成限定负例，故全部保持未判定。

现有公开材料也没有提供与 6.13.0 到 6.13.1 同合同、同候选空间但不触发配置形态变化的兼容源变更。另找一次绿色升级会改变源输入，不能作为本案例 A3，故 A3 保持 0。

## 统计与边界

- 链独立因果正例：1；
- 正目标仓：1；
- 限定负例：0；
- A3：0；
- 本地受控主三臂：1 组 A0、A1、A2；
- 修复贡献对照：4 臂，其中代码单独、依赖单独、版本字段单独均失败，完整发布物通过。

本包证明的是“Rollup 预设必须去掉 Babel CommonJS 转换”的窄合同，不证明所有使用 `babel-preset-es2015` 的项目都会失败。公开标签的目标旧版本存在偏差，已经在本包中更正而未静默继承。当前语义判断仍由构造者单人完成，进入正式保留集前需要独立复核者确认版本边界与一条关系计数。
