# H2 1.4.200 的 FSE 扩展关系族

更新日期：2026-08-25

## 结论

FSE 2024 中，目标版本为 H2 1.4.200 的完整候选框共有 16 条记录。先排除 `h2-mvcc-clients` 已完成的 5 条记录后，剩余 11 条记录折叠为 6 个新的独立根仓关系。本扩展包正式接纳 1 条：`arey/spring-batch-toolkit`；其余 5 条因不存在固定 1.4.200 的维护者 A2 而拒绝。

Spring Batch Toolkit 的证据形成完整闭环：H2 精确源提交禁止 `CREATE TABLE` 右括号前的多余逗号；公开 FSE 执行命中同一错误；目标维护者随后在升级到固定 1.4.200 的同一提交中删除该逗号；原生测试的 A0/A1/A2 方向为通过、失败、通过。

## 与既有 MVCC 包去重

完整框中的记录 2177、2181、10575、15868、15872 已属于 `h2-mvcc-clients`。它们由 H2 提交 `92692e63...` 删除 `MVCC` 连接设置支持，已经折叠成 Database Rider 与 CloudSlang Score 两条正式正关系并完成三臂。

本包保留这 5 条记录，但状态统一标为排除；不重放、不计入新的候选根仓，也不再次增加正关系。`openscore/score` 是 `CloudSlang/score` 的历史别名，node 与 orchestrator 也是同一根仓内模块。

## 新候选框

| 机制或症状 | 工作簿记录 | 独立根仓 | 裁决 |
|---|---:|---:|---|
| `CREATE TABLE` 尾逗号 | 4 | 4 | Spring Batch Toolkit 接纳；其余 3 个拒绝 |
| Fastnate 重复主键 | 1 | 1 | 拒绝 |
| Elepy 过滤结果过多 | 6 | 1 | 拒绝 |

Elepy 的 6 条断言共享同一根仓、模块、测试夹具和过滤实现，只能算一个关系。四个尾逗号失败虽然共享上游机制，但来自四个独立 Git 根仓，因此保留为四个候选关系。

## 精确源机制

H2 1.4.199 标签为 `1ceaa87e...`，1.4.200 标签为其后代 `e1bcf3b6...`，两者之间有 847 个提交。

精确变化是 `3f24dad2...`，提交说明为“禁止若干剩余位置在右括号前使用逗号”。在 `CREATE TABLE` 路径中，它移除了宽松解析：读到逗号后不再接受紧随其后的右括号。

为了排除 1.4.200 其余 846 个提交，源探针还把这一条最小语义变化移植到 1.4.199：只将建表列清单的 `readIfMore(false)` 改为严格模式，不带入同期解析器重构。四个探针方向为：

| 源输入 | SQL | 结果 |
|---|---|---|
| 1.4.199 | 保留尾逗号 | 通过 |
| 1.4.200 | 保留尾逗号 | 失败，`42001-200` |
| 1.4.200 | 删除尾逗号 | 通过 |
| 1.4.199 + 最小源变化 | 保留尾逗号 | 失败 |

## Spring Batch Toolkit 三臂

目标基准提交为 `1605c3fc...`，使用 H2 1.4.196。其 `TestParallelAndPartitioning.sql` 中最后一个字段为 `GENRE CHAR(10) NOT NULL ,`。

维护者提交 `4c467ad8...` 的父提交正是该基准。该提交只改两处：把 H2 1.4.196 升到 1.4.200，并删除上述尾逗号。原生测试 `TestParallelAndPartitioning#launchJob` 的结果为：

| 臂 | H2 | SQL | 结果 |
|---|---:|---|---|
| A0 | 1.4.196 | 保留尾逗号 | 通过，1 个测试 |
| A1 | 1.4.200 | 保留尾逗号 | 失败，精确命中 `[42001-200]` |
| A2 | 1.4.200 | 维护者删除尾逗号 | 通过，1 个测试 |

历史代码以 Java 8 为环境。当前机器只有 Java 11 与 21，因此三臂统一加入 `javax.annotation-api:1.3.2`，并将会在 Java 11 上空指针退出的 Surefire 2.20.1 统一替换为 2.22.2。第一次环境失败不计入 A1；环境补丁不改变 H2 版本、SQL、生产代码、测试逻辑或断言。

## 其余五个根仓

`btc-ag/redg`、`sea-huang/spring-data-mybatis-pagination` 与 `jaxio/celerio` 都命中相同尾逗号机制，但完整历史从未采用 H2 1.4.200。RedG 到 2025 年才在一次大规模依赖与代码迁移中删除逗号；另外两仓保留原 SQL，均没有固定版本维护者 A2。

`liefke/org.fastnate` 的重复主键错误与尾逗号、MVCC 均不同，尚未隔离到精确源提交；`RyanSusana/elepy` 的 6 个过滤断言也是另一共享症状。两仓完整历史同样没有采用 H2 1.4.200，因此没有正式 A2，停止在历史筛选阶段。

## 证据边界

本包新增 1 条正式三臂正关系和 3 个同机制但无 A2 的独立执行锚点。它不把人工删除尾逗号当成另外三仓的维护者行为，也不把 Fastnate 或 Elepy 的未隔离症状归到已知源提交。

机器可读候选、根仓裁决与历史证据分别位于 `candidate-frame.jsonl`、`root-audit.jsonl` 和 `history-evidence.json`。重放入口为 `run_three_arm.sh`，结果位于 `results/h2-1.4.200-fse-extension-2026-08-25/`。

## 独立审计

2026-08-25 的独立审计没有重跑 Maven。它从总 FSE 机器可读搜索框重新筛出 H2 1.4.200 的 11 个聚合候选；展开 Elepy 的 6 个源记录后恰为 16 条原始记录，与本包逐条 ID 完全一致。排除既有 MVCC 的 5 条记录后，11 条新记录按规范仓库别名、模块和共享测试夹具折叠为 6 个根仓；6 个根仓 ID 与仓库名均唯一，只有 Spring Batch Toolkit 被接纳。

GitHub 提交对象与比较接口另行确认：H2 1.4.199 到 1.4.200 是前向 847 提交，`3f24dad2...` 同时修改解析器与对应尾逗号测试；Spring Batch Toolkit 的 `4c467ad8...` 是基准的直接子提交，完整差异只有 H2 版本和失败 SQL 两个路径。已有结果的四个源探针全部符合预期，目标 Surefire 报告分别为 1 项通过、1 项以 `[42001-200]` 错误失败、1 项通过。

审计同时修复了重放入口的两个包内问题：临时目录现在固定在仓库 `.work/` 下，不再继承可能指向仓库外的 `TMPDIR`；运行器会核对每臂方向和 A1 精确签名、自动保存三份 Surefire 报告，并在不符时返回非零。现存 `maven-version.txt` 记录的是启动器默认 Java 21；行为命令实际都显式使用 `JAVA_HOME` 指向 Java 11，`java-version.txt` 与三臂共同环境补丁保留了这一边界，后续重放会用同一 Java 11 记录 Maven 版本。
