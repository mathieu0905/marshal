# ANTLR 4.10 FSE 五仓复核

评估日期：2026-08-25

## 结论

本轮固定 `antlr4-runtime` 4.9.3 到 4.10 的五个 FSE 独立根仓。正式旗舰关系接纳 0 条，保留 1 条机制锚点：`radkovo/jStyleParser`。

jStyleParser 在同一目标基准和同一 Java 环境下出现明确的三臂方向：

| 臂 | 运行时 | 生成器 | 结果 |
|---|---:|---:|---|
| A0 | 4.9.3 | 4.5.3 | 182 项通过，跳过 2 项 |
| A1 | 4.10 | 4.5.3 | 170 项启动，167 项错误，跳过 2 项 |
| A2 | 4.10 | 4.13.2 | 182 项通过，跳过 2 项 |

A1 的根错误是旧生成代码携带序列化版本 3，而 ANTLR 4.10 运行时只接受版本 4：`Could not deserialize ATN with version 3 (expected 4)`。A2 只把生成器改成维护者后来采用的 4.13.2，运行时仍固定为 4.10，完整解析测试恢复。

这条结果不能进入正式旗舰包。维护者提交 `66e905d079dd9f7a7b58dac9705fe284beb5876e` 同时把生成器和运行时从 4.5.3 升到 4.13.2；本轮 A2 只抽取其中的生成器一行，形成了维护者没有采用过的“生成器 4.13.2 + 运行时 4.10”组合。它证明“重新生成版本 4 的 ATN 能恢复”的机制，也证明维护者后来选择了同步升级方向，但不满足“固定新源后原样加入维护者精确修复”的正式接纳标准。

## 五仓判定

| 根仓 | 判定 | 依据 |
|---|---|---|
| `ojai/ojai` | 拒绝 | 2022-02-03 已把生成器和运行时同步到 4.9.3；仓库后续维护到 2022-12，但没有 ANTLR 协调提交，找不到固定 4.10 后的维护者 A2。 |
| `radkovo/jStyleParser` | 机制锚点 | A0/A1/A2 方向完整，但 A2 是从双版本升级中抽出的最小机制恢复，不是维护者采用过的精确组合。 |
| `threefish/nutz-sqltpl` | 拒绝 | 仓库最后一次提交在 2020-10，早于 ANTLR 4.10；运行时固定在 4.7.1，也没有本仓维护者生成器修复。 |
| `nRo/DataFrame` | 拒绝 | `develop` 在 2021-12-24 将运行时升到 4.9.3、生成器升到 4.9.2，之后无 ANTLR 维护动作；找不到 4.10 后 A2。 |
| `locationtech/geowave` | 拒绝 | `core/store` 从引入起一直使用生成器和运行时 4.7.2；主分支及 2.x 分支均没有后续 ANTLR 修复。 |

五条记录全部来自同一 `antlr4-runtime` 4.9.3 到 4.10 候选框。同仓模块没有拆成独立根仓；FSE 0287、0288 使用的是 `org.antlr:antlr4`，没有混入本框。

## jStyleParser 历史动作

目标基准固定为 `aed9ffc08dda481222bd9cd66635116768e23a54`。2024 年维护者分支在它之上先用 `20f0d40bfaed8fee7549d80f47b5c3fabc254895` 把 Java 8 升到 11，再用 `66e905d079dd9f7a7b58dac9705fe284beb5876e` 同步升级 ANTLR 生成器和运行时，最后由合并提交 `afec854a12632c1d2ecd64a3e83ca4cd2e076bae` 合入。

三臂全部在原目标基准上以 Java 11 执行，因此 Java 升级没有混入 A2。`maintainer-full-update.patch` 保存维护者原始双版本动作，`a2-mechanism-combination.patch` 保存本轮只抽取生成器行并固定 4.10 运行时的干预。两者必须同时阅读，不能把后者描述成维护者原样修复。

A2 会打印生成器 4.13.2 与运行时 4.10 版本号不一致的警告。警告不影响本次机制恢复判断：两个版本都生成或读取序列化版本 4，完整 182 项解析测试通过。但这个警告进一步说明 A2 是实验性隔离组合，而不是项目维护者认可的长期依赖组合。

## 源变化

版本端点固定为：

- 4.9.3 标签提交：`e4c1a74c66bd5290364ea2b36c97cd724b247357`；
- 4.10 标签对象：`02e66ccd31559cb96c9dc684df56c568aebd7533`；
- 4.10 标签提交：`c7567ba9bb40c361dda60e60e2bc932a16d2adf8`。

4.10 版本把 ATN 序列化版本从 3 改为 4。提交 `c68e127a7cf14470565d6e6ae1eff06db3e56ea7` 又撤销了 Java 运行时对版本 3 的临时兼容处理，形成 A1 中直接观测到的拒绝路径。`source-runtime-incompatibility.patch` 保存这一精确来源证据。

## 证据边界

FSE 原记录只证明依赖更新时出现过执行失败，不提供维护者修复。正式标签仍要求本轮独立恢复 A0/A1/A2，并要求 A2 来自目标维护者的精确动作。

jStyleParser 的 182 项恢复可以用于解释故障机制和检验检测器是否能建议“同步生成器”，但不能计入旗舰严格正例数量，也不能让 ANTLR 形成完整项目包。其余四仓没有用人工修复补齐 A2，也没有把普通绿色或后续任意版本升级当作恢复证据。
