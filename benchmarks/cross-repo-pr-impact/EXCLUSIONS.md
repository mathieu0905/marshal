# 纳入、排除与候选记录

## 正式集标准

- 以唯一源 PR 为案例单位，同一源的多个目标聚合保存；
- 源与目标属于不同仓库，双方均已合并；
- 目标必须有人工核验的规范实现、非规范语义适配、持续集成对照或固定版本执行证据；
- 普通 `Depends-On`、配套链接或绿色任务不能单独成为影响标签；
- 源输入必须恢复到 PR 创建时或 Gerrit 补丁集 1；
- 目标 PR 完整改动路径必须可取得；
- 每个正式目标仓在观察截止时间前必须有可用代码版本；
- 同一 PR 不能同时作为不同正式案例的源和目标。

## GitHub 多实现候选

完整搜索框有 1232 条目标引用、926 个唯一源 PR和 36 种初始仓库关系。43 次查询均记录实际命中、抓取数量、稳定排序、搜索上限和不完整状态，本次没有截断。

机器从中构造 180 条关系多样复核池，160 条进入人工可判范围。人工实际复核 108 个源案例，接受 102 个、拒绝 6 个；逐目标接受 191 个、拒绝 18 个。具体理由见 `candidates/github-multi-target-manual-review.jsonl`。

接受后恢复开单快照，101 条成功。`rust-lang/rfcs#16` 是唯一失败项：2014 年当前提交链中没有创建时间前提交，也没有可用于恢复的强推前头提交，因此排除，不能用最终差异替代。

正式集从 101 条可用项中选择 85 条。全部 59 条多目标仓案例优先保留，再按源仓到目标仓关系轮转选择 26 条单目标案例。未选中的 16 条仍保留在候选、人工复核和时间恢复记录中；它们不是质量拒绝项。

搜索只匹配目标 PR 正文中的完整源 PR 链接。裸编号、提交说明和间接 issue 引用不在抽样框中。

## OpenDev 候选

旧的普通协调采集框保留 1055 个链独立候选。只有明确尾注而无额外因果或语义证据的案例不进入正式集。

从该框中人工挑选 13 条非规范关系，要求目标提交说明具体解释源变化如何被消费、暴露、配置或验证。13 条均通过补丁集和目标证据复核。三个曾考虑案例因目标创建早于源变更而排除：Cinder 962409 到 Glance Store 962408、Requirements 976640 到 Nova 976390、Neutron Lib 983203 到 Neutron 983201。

Cinder 1001023 因有同任务失败到修复对照纳入。WanderTracks 1001388 因有固定版本组合执行证据纳入。

## 不自动生成的标签

- 不把协调语法方向称为真实影响方向；
- 不把目标 PR 全部文件写入人工影响位置；
- 不按路径名猜测试或按关键词猜影响类型；
- 不因绿色任务地址就声称跨仓组合已证明；
- 不用最终 PR 内容替代无法恢复的开单输入；
- 不把同生态干扰仓当成负例。

## 无影响对照

当前没有可靠的“完全无跨仓影响”案例。没有配套 PR、没有搜索命中、仓库当时尚未创建或流水线通过都不能证明不存在影响，因此不构造弱负例，也不报告误报率。
