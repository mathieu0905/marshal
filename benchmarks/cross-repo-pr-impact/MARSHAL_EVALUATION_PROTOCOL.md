## 目的

本文件定义如何把跨仓数据输入 Marshal，以及什么结果可以被称为“Marshal 当前成绩”。核心要求是区分现有确定性配置覆盖和完整审查流程，避免把配置未命中、模型记忆或人工分析混成同一个数字。

数据集负责提供已知候选仓目录。这里不评测开放世界仓库发现；完整审查流程的任务是在同一候选目录内读取代码并排序。E1 历史适配和 E2 因果破坏复用输出格式，但分别报告。

## 当前接口事实

Marshal 的确定性入口以单个源仓变更为单位。`CowboyPack` 根据源仓别名和修改路径匹配预先登记的跨仓契约，再由不变量中的 `location_repo` 给出需要检查的仓库。它具备表达跨仓关系的能力，但关系来自领域包配置，不会从一组陌生候选仓代码中自动发现。

现有审查技能可以读取工作区、构造变更闭包、调用审查视角并运行目标仓不变量，但它的正式输出是风险等级、发现和门禁建议，不是候选仓排序。现有入门流程也只为单仓生成概念页，没有生成项目级仓库关系图。

因此当前有两个不同问题：

1. 已配置契约是否覆盖给定变更；
2. 在没有预登记目标映射时，完整审查流程能否从数据集提供的候选仓代码中定位和排序需要检查的仓。

两者必须分开运行和报告。

## 轨道一：现有配置覆盖

`evaluate_current_marshal.py` 将每条校准案例的源仓别名和源修改路径交给当前 `CowboyPack`，把命中的跨仓不变量目标仓转换为评测预测。它不读取候选仓代码，也不调用模型。

2026-08-23 实测结果：

| 项目 | 结果 |
|---|---:|
| 案例数 | 100 |
| 有任意已配置契约命中的案例 | 0 |
| 已知目标宏平均召回 | 0 |
| 平均倒数排名 | 0 |
| 前 1、3、5 项召回 | 0 |
| 平均预测仓数 | 0 |

结果位于 `results/current-marshal-score-2026-08-22.json`。文件名沿用现有脚本名称，实际重跑日期记录在本文件和审计文档中。

该结果证明的是当前 Cowboy 专用配置不能直接覆盖陌生生态。它不证明完整审查流程无法发现这些影响，也不应与简单仓库排序策略直接比较。普通 Git 仓库结构、版本号、类型信息和单仓测试只能提供局部证据，不能凭空补出未配置的仓库关系；这正是该轨道为零的具体原因。

## 轨道二：离线多仓审查

完整能力实测必须使用 `prepare_case_inputs.py` 生成的目录，并在推理阶段关闭网络。每次运行只能读取：

- `source.patch` 和 `input.json`；
- `repositories/` 下所有候选仓的截止时点代码；
- `repository-snapshots.json` 中的仓库名称和版本信息；
- Marshal 本身公开的领域无关审查流程。

准备目录本身还必须通过输入可见性复核。2026-08-24 的复核发现，OpenDev 下载的邮件格式补丁会把提交说明中的 `Depends-On` 或配套变更地址写入 `source.patch`。因果试采六条中有三条因此直接泄漏目标变更，一条点名目标仓。这些案例在统一生成纯代码差异前不能用于无提示仓库检索主分数；强因果标签本身不受影响。逐例证据见 `causal-pilot/input-visibility-audit.jsonl`。

不得读取隐藏标签、目标修复、持续集成记录、候选采集记录或评测结果。不得事先为正式案例写入源仓到目标仓映射，也不得用正式标签生成领域包规则。

### 输出适配

现有 Marshal 门禁结果不能直接评分。实测时需要一个只负责格式转换的评测适配提示，要求审查流程在完成代码分析后额外输出 `prediction-schema.json` 规定的候选仓排序。适配层不得包含项目名称、目标线索、影响类型或历史答案，也不得改变 Marshal 的风险分类和审查逻辑。

这一路径应明确命名为“Marshal 审查流程加评测输出适配”，不能简写成当前确定性配置。若以后产品原生支持多仓候选排序，再单独报告原生接口成绩。

### 运行条件

- E1 开发材料先用于调试输入和输出，不用于按答案调规则；候选目录 provenance 和关系隔离 split 完成前不产生正式分数；
- E2 已有 50 条机器验证关系标签；候选选择按唯一源事件合并多目标计分，不能把
  重复输入的关系行当作独立题目。产品执行仍因发布包重放材料不闭包而只能逐例诊断；
- 每例最多报告 5 个仓库，完整保留排序和不报告任何仓库的情况；
- 固定模型、推理强度、上下文上限和运行次数；非确定性流程至少重复 3 次，同时报告单次结果和稳定命中率；
- 同一协议用于所有可比系统，网络、候选仓代码、输出数量和时间边界必须一致；
- 执行失败、上下文溢出和无法解析输出分别记录，不能改写成“无影响”。

### 2026-08-24 原生接口开发实测

选择未发现目标线索的 `causal-opendev-1000668`，物化了协议规定的可见输入：1048 字节源差异、14 个候选仓、24614 个文件，展开约 223 MiB。三个确定性命令只接收仓库名、修改路径和源差异，没有传入隐藏标签、目标修复或构建证据。本次接口诊断没有建立文件系统级沙箱，因此它只证明当前命令参数和代码路径没有消费这些材料；将来运行模型审查时仍必须另行实施离线和文件可见性隔离。

当前原生命令的实际结果为：

| 环节 | 结果 |
|---|---|
| `classify` | 中风险，未命中契约，列出正确性、规范和跨仓三个维度 |
| `invariants` | 空列表 |
| `review-lenses` | 只有正确性视角属于领域无关；规范视角询问 CIP，跨仓视角限定编码和类型序列化，二者是 Cowboy 专用且不适配本例 |
| 候选仓代码读取 | 0/14；上述命令没有候选目录参数 |
| 仓库排序 | 不支持；没有原生排序输出 |

因此这次运行不能记为“未找到影响”，也不能给 Marshal 记零分。准确结论是：现有确定性入口在配置未命中后只留下一个领域无关审查视角和两个不适配的 Cowboy 专用视角；十四仓代码没有进入任何原生命令，完整多仓审查仍需要评测输出适配或新的产品接口。机器记录位于 `results/current-marshal-offline-development-2026-08-24.json`。

商业产品的“跨仓”功能不自动满足上述条件。当前官方资料核对显示，CodeRabbit、Qodo 和 Greptile 的完整跨仓审查都依赖已接入的远程仓库，且会受到关联仓数量、默认分支或内部候选选择限制；Bito 的本地 AI Architect 能读取多仓目录，但只是检索组件，不直接输出审查发现或仓库排序。详细证据见 `COMPETITOR_RUNNABILITY.md`。

因此只有实际读取同一离线目录并产生统一排序的系统进入主表。必须镜像仓库、联网或使用产品原生合并请求的运行，单独标为托管沙箱重放；只替换索引与检索层的运行，单独标为组件对照。不同类别不得按同一分数解释。

## 结果解释

主表报告已知目标召回、平均倒数排名、前 1、3、5 项召回和预测数量。由于标签不完整，额外仓库只记为未判定，不报告精度、误报率或停止能力。

同一源事件存在多个已知目标时，MRR 取第一个相关目标的倒数排名，Recall@K 取
top-K 找回目标数除以该事件全部已知目标数；检查位置和可运行检查也对全部已知目标
计分。50 条 relation-level strict-E2 标签可以用于 repair 轨道，但 retrieval 的分母
不得仍写 50。

失败分析至少区分：

- 当前领域包没有该生态配置；
- 找到契约变化但没有定位目标仓；
- 定位到目标仓但排序靠后；
- 只依赖仓库名称或生态常识；
- 读取代码后给出可核对的跨仓证据；
- 输入准备、上下文或执行工具失败。

## 当前产品链路状态

dashboard deep worker 已接入 `ReviewRun`：在模型进程前开 run，独立记录 Git
head/base/tree 与实际 argv，在 `GateRun` 前关闭；命令失败留下 degraded run，缺失
结构化步骤或外部扫描证据的 `pass` 降为 `needs_human`。这修复的是证据链断开，
不是对模型自报步骤真实性的额外证明。

ratchet 关闭现在原子保存永久检查的 argv 与源仓/路径触发范围；复发事件会把匹配
的 active ratchet 合入 `Orchestrator.plan`，无关路径不调度。三条顺序任务的登记率、
复发调度率、无关控制克制率均为 1.0；复发执行、失败证据、阻断和端到端率仍为
`not_assessed`/0，因为发布包没有对应执行工作区。

## 下一步准入

在满足以下条件前，不发布 Marshal 与竞品的跨仓优劣结论：

1. 评测适配提示经过无标签案例检查，确认不含答案线索；
2. 至少完成一批校准案例的离线多仓试运行，证明输出可解析且没有访问禁区；
3. 公开 evaluation 使用现有隔离组；真正 blind holdout 使用从未公开的新案例或
   私有 evaluator，不能把已公开 E2 标签重新命名为盲测；
4. Marshal 和可比系统使用完全相同的输入、网络限制与输出预算。

这不是新增产品门禁，也不修改 Marshal 产品代码；它只是把当前能测到的配置覆盖与尚待实测的多仓发现能力分开。
