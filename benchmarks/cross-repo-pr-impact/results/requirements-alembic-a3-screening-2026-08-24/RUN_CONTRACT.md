# requirements 项目包 A3 筛选合同

日期：2026-08-24

## 研究问题

Alembic 1.17.2 到 1.18.0 这一真实相邻发布，在不修改候选仓代码的情况下，能否保持固定闭集的 MySQL 模型同步测试通过。

1.18.0 重组了自动生成比较功能，引入插件体系，并改变部分数据库的反射路径。这里评价完整真实发布，不把结果只归因于某一处内部提交。零假设是该变化会使至少一个固定消费者的原生命令失败；备择假设是前后两臂都通过。

## 固定输入

- 约束基底：requirements `b8de3b00af9dd2ffc1a85bf836cf3c7ee9e8bac7` 的完整 `upper-constraints.txt`；
- A3 前臂：只把 Alembic 固定为 1.17.2；
- A3 后臂：只把 Alembic 固定为 1.18.0；
- 数据库：与三臂试验相同的 MariaDB 10.2.44 临时实例；
- Python：3.13；
- 候选闭集：Cinder、Heat、Ironic、Keystone、Nova、Placement 的覆盖审计固定提交。

先只在 Cinder `b5b763129e2bde5077c0cf3a5eb434021abaa6e0` 上执行同一条 `TestModelsSyncMySQL.test_models_sync`。前后均通过且实际版本正确，才准备五个干扰仓；任一臂出现安装、连接或测试发现问题，先归因，不把环境失败写成不兼容。

## 证据强度

所有候选测试都执行 Alembic 自动生成元数据比较，因此覆盖 1.18.0 的新插件组织路径。当前合同不预设它们会触发 1.18.0 每个数据库专有分支；正式结论必须限制在已执行的模型同步命令，不能扩张为 Alembic 1.18.0 的一般兼容性。

本轮是 A3 筛选，不是三次正式重复。筛选结果不能单独产生限定负标签。
